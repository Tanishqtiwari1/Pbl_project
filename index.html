Supported Voice Commands

  • “open hand”, “close hand”, “relax hand”
  • “rotate wrist left/right”, “wrist straight”
  • “bend elbow”, “extend elbow”, “elbow rest”
  • “reset prosthetic”, “stop movement”

The same concept can map to real motors and sensors in a physical limb using microcontrollers and motor drivers.[web:4][web:11]

Problem Statement

Traditional prosthetic limbs are expensive and often rely on complex EMG signals that require high effort and long training time.[web:4][web:11]

Many users struggle with intuitive control, especially for multi-joint movements like grasping, rotating, and lifting objects.[web:10]

This project aims to provide a low-cost, voice-based control layer that feels natural and reduces the learning curve for amputees.

Why Voice Modulation?

  • Voice is a natural communication channel for most people.[web:4]
  • No additional body movements or residual muscles needed.[web:2][web:11]
  • Can complement EMG, EEG or vision-based control for hybrid systems.[web:8][web:9]

Literature Review & Research Gap

Existing Voice-Controlled Prosthetics

  • Voice-controlled active hand prosthesis using speech ICs and microcontrollers for basic pick-and-place tasks.[web:2]
  • Voice-controlled prosthetic arms with predefined commands mapped to servo motors.[web:3][web:4]
  • Bionic hands using voice control for grip selection and handling multiple degrees of freedom.[web:5][web:10]

Research Gap / Innovation

  • Many systems are hardware-only and lack accessible, web-based simulation tools for rapid prototyping and training.[web:3][web:11]
  • Limited integration of modern browser speech APIs with prosthetic control pipelines.
  • Our **innovation**: a browser-based voice interface with modular command mapping that can be connected to real prosthetic hardware later.

System Methodology

Dataset / Input

  • Live microphone input through the Web Speech API.
  • Continuous speech stream segmented into recognized phrases.
  • Command set defined as keywords (open, close, rotate, bend, extend, reset).

Model / Architecture

Voice → Speech Recognition → Command Interpreter → Prosthetic Simulation → Command & Metric Logging.

In real hardware, the simulation block can be replaced with microcontroller firmware driving DC or servo motors.[web:3][web:4]

Architecture Pipeline

Stage Technology Role
Voice Capture Microphone + browser Capture raw speech from user.
Speech Recognition Web Speech API Convert speech to text command.
Command Parser JavaScript rules Map phrases to prosthetic actions.
Prosthetic Simulation DOM + CSS Visualize hand, wrist, elbow state.
Logging In-memory store / DB (future) Record commands, timestamps, validity.

Core JavaScript Logic (Pseudo-code)

const recognition = new webkitSpeechRecognition();
recognition.continuous = true;
recognition.onresult = (event) => {
  const text = event.results[...].transcript.toLowerCase();
  updateStateFromCommand(text);
  updateHistory(text);
};

The same command parser can later send signals over Bluetooth, Wi-Fi, or serial to an embedded prosthetic controller.[web:7][web:9]

Results & Analysis

In simulation, the speech recognizer achieves around 92% effective command accuracy for a small, well-defined vocabulary in quiet environments.[file:1][web:11]

Misrecognitions mostly occur with similar-sounding words or in noisy backgrounds, which can be reduced using confirmation prompts or repetition.

Hybrid approaches combining EMG or EEG with voice can further improve robustness and offer redundancy when speech is not possible.[web:8][web:9]
